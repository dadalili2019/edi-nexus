## 已完成

### 1. 旧系统复盘

已对几年前的 `Micro-DataExchangeService` 进行静态架构分析。

确认旧系统真实主链大致为：

```mermaid
flowchart LR
    EXT[外部系统] --> R[Reception]
    R --> K1[Kafka]
    K1 --> S1[Sending：记录与派发]
    S1 --> K2[Kafka]
    K2 --> W[Writing：校验与落库]
    W --> K3[Kafka 回执]
    K3 --> S2[Sending：更新状态]
```

旧版的 Sending 并不是真正完整的“对外发送服务”，主要承担内部派发和状态回执。

### 2. 已确定新版不直接改旧系统

旧系统作为参考样本。

新版重新设计，但继承其中合理的思想。

### 3. 已确认值得继承的思想

- 接收与业务处理分离
- 统一内部消息
- 合作方 / 场景 / 版本差异隔离
- 业务校验与系统校验分离
- 处理阶段固定、差异实现可替换
- 异步解耦
- 状态回流与追踪

### 4. 新版必须重点解决

- 明确消息状态
- 失败处理
- 自动 / 人工重试
- 幂等
- 数据一致性
- 消息追踪
- 日志关联
- 多实例
- Kubernetes
- Pod 重启 / 终止
- 可观测性
- 健康检查
- 管理平台
